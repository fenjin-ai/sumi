# Direct on-device capability probe

Research only; no production integration. This standalone Swift program calls
Foundation Models directly, avoiding the app's rule resolver. It requires
macOS/Xcode 27 for capability introspection and image attachments; this does not
change LeftBlank's deployment or CI SDK requirements. Text/model behavior is not
assumed to be identical on macOS 26 or iPad.

Inputs are owned synthetic texts and page fixtures. The only tools search three
synthetic records or count whitespace-separated words. No manuscript/library
reads, cloud model, DB, Hurl, OrbStack or persistent application changes occur.

`cases.json` was fixed before the first run (115 requests). `holdout.json` adds
30 requests across new subjects, including six explicitly localized tagging
prompts. After observing ambiguous category boundaries, `taxonomy-defined.json`
retests 12 existing cases with explicit definitions; this is prompt development,
not a fresh holdout. `stability.json` repeats the 12 defined classifications and
six localized tagging requests. `boundary.json` is a separate true-overflow
test. The initial 8,001-input-token context case fits the observed 8,192-token
budget despite its intended overflow label; do not count it as a model error.

Each call uses a fresh session and a task-specific dynamic schema. Tagging calls
use `.contentTagging`; other calls use `.default`. Sampling temperature is zero
and the response budget is 512 tokens. Raw results preserve errors, tool calls,
token-count probes and timings. Timings include token counting, not just
generation. Image token counting was unavailable in these observations.

`score.py` checks exact fields, source quotes, required content, actual tool
routes and arithmetic against fixed expected values. Unit suffix normalization
is a separate extraction metric, never a rewrite of the strict score. Code is
compiled with the real Tinymist after excluding file/package access; compilation
does not establish requested behavior. `manual-reviews.json` records this
assistant's explicit relevance/fidelity/semantic reviews. It is not an
independent human or blind evaluation.

## Reproduce

Use an SSD worktree, an available Apple Intelligence model, and no simultaneous
model workload. Set the image root to the owned fixtures generated by
`../intelligence-evaluation/build-pages.py`. Native Chinese, column and table
PDFs should be rendered to matching PNG names with Poppler `-scale-to 1100`.
`results-2026-10-03/image-manifest.json` records exact first-run image hashes and
dimensions. PNG inputs are kept outside Git on the SSD.

```sh
source scripts/environment.sh
swiftc -parse-as-library -swift-version 6 \
  -module-cache-path build/device-capabilities/module-cache \
  design/device-capabilities/probe.swift -o build/device-capability-probe
capability_output=$(mktemp -d /Volumes/SSD/Developer/Codex/tmp/device-capabilities.XXXXXX)
LEFTBLANK_CAPABILITY_IMAGE_ROOT=/absolute/SSD/path/to/owned-fixtures \
  build/device-capability-probe design/device-capabilities/cases.json "$capability_output"
python3 design/device-capabilities/score.py design/device-capabilities/cases.json "$capability_output"
```

Run each additional JSON file sequentially with a separate output directory.
The scorer requires the installed `.tools/tinymist`. All temporary files,
generated source, PDFs and compiler caches stay on the external SSD.

The [capability report](../../docs/device-model-capabilities-2026-10-03.md) makes
product recommendations with explicit limitations. Saved raw runs are in
`results-2026-10-03/`; production code and the original app-effect baseline were
not changed by this probe.

The saved `.typ` preview copies strip trailing spaces and blank lines at EOF
for Git. Exact model output remains in the observations JSON; scoring and
compilation used that original output.
