# Code notes and executable blocks

The built-in Sumi guide includes a numbered code example using version-pinned [Codly](https://typst.app/universe/package/codly/). Command-N opens Templates, where the guide and a blank page are always available offline. The old standalone Code notes creation action and default-template picker have been retired. Existing Code notes documents and persisted preferences remain readable; their Codly and codly-languages packages are still bundled. Source exports retain explicit imports and work in other Typst editors.

Codly formats code; it does not execute Python, shell scripts or other languages. Sumi currently displays code blocks only. This iteration does not ship an executable-block runner or automatically execute code imported from a document or generated by an agent.

A later Babel-like feature should use explicit, per-block Run actions and an independently cancellable process runner. Start with one language, a specified interpreter, a document-owned working directory, bounded execution time/output and visible provenance for results. Do not assume a subprocess is sandboxed. Imported documents start untrusted and execution requires a deliberate user action; typing, previewing, opening a document, package imports and MCP document edits never execute code implicitly. Output should appear in an adjacent result block that can be inspected and undone, with a source hash marking stale results when the code changes. Long-running processes must not share the editor's actor or block Tinymist.

Cost is moderate for a local Python proof of concept, but higher for a trustworthy multi-language experience: interpreter discovery, environments/dependencies, cancellation of process trees, filesystem/network permissions, reproducibility and rich result rendering are separate product decisions. Keep code-listing style independent of the runner so we can improve reading now without committing to execution semantics.
